# 納品チェックリスト(下書き)

> **本ドキュメントは、実際の納品時に使うひな形です。**
> 本プロジェクト(`line-bot-app`)は美容室オーナー向けを想定した**模擬案件(練習用プロジェクト)**であり、
> 実在のクライアントへの納品は行っていません。将来、実際に納品する場面で開発者(自分)が使うための
> チェックリストのひな形として用意しています。

このチェックリストは、`README.md`・`docs/owner-manual.md`・`docs/setup-guide.md`・`docs/technical.md`・
`supabase/migrations/`・コード(`app/`、`lib/`)を実際に読んで作成しています。
コードや既存ドキュメントから確認できない運用・契約上の判断は **【要確認】** と明記しています。
**キー・トークン・ユーザーIDなどの実際の値は、このファイルには一切記載しません。**

## 1. 事前準備(お客様側のアカウントの用意)

お客様自身の事業として運用してもらうため、原則すべてお客様名義のアカウントで契約する想定です。

- [ ] **LINE公式アカウント**: お客様名義で開設されているか確認する。
- [ ] **LINE Developers(Messaging APIチャネル)**: お客様のLINE Developersアカウント・プロバイダーでチャネルを作成する(`docs/setup-guide.md` 4-1章)。開発者が代理で作成した場合は、納品時にお客様名義へ権限を移すか、最初からお客様名義で作業する。
- [ ] **Vercel**: お客様名義のアカウント/プロジェクトで契約する。プランは、`docs/technical.md` 8章の指摘どおり、無料のHobbyプランは「非商用の個人利用のみ」のため商用納品では**Pro相当の有料プランが必須**(Vercel公式: https://vercel.com/docs/plans/hobby より確認済み)。
- [ ] **Supabase**: お客様名義で**専用の新規プロジェクト**を用意する(検証環境では他アプリ(`mitsumori-app`)と共用しているため、納品時は分離する)。Free Planは「1週間アクセスがないとプロジェクトが一時停止(pause)」する制約があるため(`docs/technical.md` 8章)、来店・LINE利用が少ない店舗ではプラン要否を判断する【要確認: 最終的にお客様がどのプランを選ぶか】。
- [ ] **Anthropic(Claude API)**: お客様名義のアカウント/組織でAPIキーを発行する(`docs/setup-guide.md` 5章)。従量課金のため、想定利用量に対する料金目安を事前に説明しているか確認する。
- [ ] **GitHub**: ソースコードの引き渡し先リポジトリ(お客様名義 or 開発者管理のままでアクセス権のみ付与するか)を事前に決めておく【要確認: 本プロジェクトでは契約形態が未定のため、どちらにするか案件ごとに確認】。

## 2. 設定の引き継ぎ

- [ ] 環境変数をVercelのお客様プロジェクトに登録する(`.env.local.example` に記載の名前のみ。値はここに書かない)。

  - [ ] `NEXT_PUBLIC_SUPABASE_ANON_KEY`
  - [ ] `SUPABASE_SERVICE_ROLE_KEY`
  - [ ] `LINE_CHANNEL_ACCESS_TOKEN`
  - [ ] `LINE_CHANNEL_SECRET`
  - [ ] `ANTHROPIC_API_KEY`
  - [ ] `OWNER_LINE_USER_ID`
- [ ] LINE Developers Consoleの「Messaging API設定」で、Webhook URLを `https://<本番ドメイン>/api/line-webhook` に設定する(`README.md` 8章)。
- [ ] 「Webhookの利用」を**オン**にする(`docs/setup-guide.md` 4-2章)。
- [ ] LINE Official Account Managerの応答設定(トーク設定)を以下の通りにする(`README.md` 8章、実際にLINEから動作確認済みの設定)。
  - [ ] Webhook: オン
  - [ ] チャット: オン
  - [ ] 応答メッセージ: オフ
  - [ ] あいさつメッセージ: オフ
- [ ] 環境変数を登録・変更したら、Vercelで**Redeploy**を実行する(反映は次回デプロイ時のみ。`README.md` 8章、`docs/setup-guide.md` 9-2章)。
- [ ] Supabaseの管理者ユーザーを作成し(Authentication → Users → Add user)、そのユーザーの`id`(UUID)を `bot_admins` テーブルに登録する(`docs/setup-guide.md` 3-3章)。【要確認: 「Add user」後の具体的な入力項目は未確認】
- [ ] `supabase/migrations/` のSQL(`0001`→`0004`、番号順)を、お客様の本番Supabaseプロジェクトに適用済みであることを確認する。

## 3. 動作確認(本番環境で)

- [ ] FAQ応答: 登録済みFAQの内容、および言い換えた質問に対して正しく回答が返るか。
- [ ] エスカレーション通知: 確信度`low`と判定されたとき、**オーナー本人のLINE**(`OWNER_LINE_USER_ID`で指定した宛先)に通知が届くか。
- [ ] スタンプ・画像の扱い: スタンプ送信時に無応答(ログにも残らない)、画像・動画・音声・ファイル・位置情報送信時に案内文が返り、会話ログには種類表記(`[画像]`等)のみが記録されるか(`docs/technical.md` 2章)。
- [ ] 管理画面でのFAQ更新: `/admin` の「FAQ」画面で追加・編集・削除ができるか。
- [ ] 管理画面でのメニュー更新: 「メニューと料金」画面で追加・編集・削除ができるか。
- [ ] お知らせ配信のテスト送信: 「お知らせ配信」画面から**テスト送信(自分だけ)**を行い、オーナー自身のLINEに届くか確認する。全員配信は無料メッセージ通数を消費するため、納品確認では原則テスト送信のみに留める。
- [ ] 会話ログの記録: ユーザー発言・bot発言が「会話ログ」画面に記録され、確信度バッジ・「要確認」バッジが正しく表示されるか。
